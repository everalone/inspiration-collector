# v0.2.0 版本说明

本版重点是让收集任务可恢复、失败可处理，并避免重复收藏和中断重跑损坏已有内容。本文件记录改动与验证范围；安装包与正式发布状态以 GitHub Releases 的实际结果为准。

## 收集与任务恢复

- 手动输入、剪贴板和手机收件箱共用持久化串行任务队列。分析期间继续复制第二篇文章会排队，不再直接漏掉链接。
- 界面提供等待、处理中、已完成、失败状态和原因；提交成功只表示已排队。普通未完成任务可在应用重启后恢复，已完成任务不会因为历史记录而自动重跑。
- 普通重复收藏跳过模型提取，保留已有卡片和手动修改。
- 显式「重跑」仍需用户确认，成功后替换该文全部卡片，包括手动修改；不自动合并或备份。执行中断的显式重跑会等待用户检查后决定是否重试，避免自动重复覆盖。
- 剪贴板提交暂时失败时保留待提交链接，在连接恢复后重试。核心服务统一调度收件箱，桌面壳只观察任务并发送通知。
- 文章与图片下载的 20 秒超时覆盖响应正文，避免连接成功后卡住整个队列。任务完成后的界面刷新若暂时失败，会在下一轮重试。

## 卡片与原图完整性

- 文章元数据与卡片替换在同一数据库事务中完成；写入失败一起回滚。
- 每次重新提取先准备独立的图片目录，成功提交后才切换。抓取、图片下载、模型输出校验或写库失败时，继续保留旧卡片和旧原图。
- 新图片使用明确清单确定顺序，旧图片目录采用数字顺序，修复 `img-10` 排在 `img-2` 前造成的画廊、裁剪图错位。
- 卡片列表分页加载完整筛选结果，不再静默截断到 500 张；较早返回的搜索请求不会覆盖更新的搜索。
- 无效或不完整的模型返回会报错；网址探活得到的失效状态会写入卡片。
- 正在收集或等待重跑的文章暂不允许删除，避免删除后被后台任务重新写入。

## 手机收件箱

- 服务器仍然只中转文章链接、备注和任务状态。文章抓取、模型调用与卡片入库在桌面电脑上进行；电脑离线期间链接留在云端等待。
- 分析失败默认总计尝试 3 次，第 1、2 次失败分别退避 60、120 秒，最终失败可查看原因并手动重新排队；重新分享失败文章也可重试。
- 处理结果先保存本地回执，再向服务器确认。确认网络失败只补发 ACK，不重新调用模型；重启后继续补发。
- 收件箱请求有 15 秒超时，包含响应正文；界面显示连接错误和待确认数量。
- 服务端 ACK 支持重复提交；队列原子落盘，默认保留 30 天终态历史、最多 10000 条记录，满时优先回收已完成历史，不静默丢弃待办。
- 保持个人单用户、单桌面消费边界：一个 Token 对应一个共享队列，没有多用户隔离、多个桌面领取租约或完整卡片跨设备同步。

## 配置、开发与隐私

- 新安装的 API Key、收件箱地址和 Token 默认为空，手机收集默认关闭；他人下载安装后需自行配置，不会自动使用作者服务器或模型账户。
- 数据库存本机，但模型分析会发送文章图文给用户自己配置的模型服务；文章抓取访问微信/CDN，网址校验访问目标站点，可选收件箱接收链接和处理状态。
- 用户密钥本地保存，不随源码或安装包发布。请求时分别向用户指定的模型服务、收件箱鉴权。
- 任务错误、收件箱连接错误和失败回执按实际配置的密钥值脱敏。
- 开发态默认使用项目目录 `data/`、`assets/`；打包版使用 `%AppData%\灵感收集\`。显式指定数据目录时使用该目录配置，避免开发、测试与正式库串用。
- `npm run app` 先编译核心再启动；本机端口被占用时报告错误，不复用可能属于另一数据目录的旧服务。
- 发版流程增加类型检查、回归测试和安装包内容检查。

## 升级步骤

1. 在托盘选择「退出」，完整备份 `%AppData%\灵感收集\data/` 与 `assets/`。配置包含个人密钥，不要公开备份。
2. 更新桌面安装版或 Portable，继续使用原数据目录；旧卡片和图片目录保持可读。
3. 已部署收件箱的用户另行备份云端 `inbox.jsonl`，更新 `inbox/server.mjs` 并重启。桌面升级不会自动修改云服务器。
4. 手机快捷指令地址、Token 和提交格式不变。完整重试能力需新版桌面配合新版收件箱；旧服务端仍可基本收集，但不支持失败列表与新的重试接口。
5. 打开任务面板确认配置、连接与已有内容。需要更新旧提取结果时，再主动选择文章重跑。

详细服务器配置和验收步骤见 [公网收件箱说明](../../inbox/README.md)。

## 验证范围

仓库回归测试使用临时数据目录、测试 Token、模拟网络/模型与本地 HTTP 服务，覆盖任务串行与恢复、重复收藏保护、ACK 断线补发、超时释放、失败重试、原子写入失败、图片顺序、数据库回滚、超过 500 张卡片的分页和界面错误状态。可通过 `npm run typecheck` 与 `npm test` 执行。

本轮类型检查和 55 项回归通过。临时测试库的实际浏览器验收确认了 603 张卡片完整显示、模拟文章成功后自动增至 604 张、失败原因与重试入口，以及第 11 张图片的正确顺序。

Windows 安装版与便携版构建成功；包内容检查确认未包含个人配置或数据，并在打包后的运行时验证了空密钥/空收件箱默认值、SQLite、图片处理、卡片墙和本地接口。

这些检查不等同于真实云服务器部署、iPhone 快捷指令全链路或真实收费模型的验证；本说明不宣称已经完成上述实测。Windows 安装包仍未签名，代码签名不在本版范围内。
