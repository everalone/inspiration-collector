# v0.2.2 · 微信 ClawBot 收集、有限重试与失败报告

把公众号文章的文本链接发给自己绑定的 ClawBot，即可加入个人收件箱；电脑导入完成后，机器人会回复文章名。本版同时优化模型卡片格式兼容、具体字段报错和任务恢复，手机文章每轮最多处理 3 次，最终失败后停止并返回报告。

本次公开发布包含 v0.2.0 之后的 ClawBot 桥接、文章标题回执及 v0.2.2 的校验与重试改进。

## 下载与首次使用

- [Windows x64 安装版 · InspirationCollector-Setup-0.2.2.exe](https://github.com/everalone/inspiration-collector/releases/download/v0.2.2/InspirationCollector-Setup-0.2.2.exe)：支持选择安装目录，创建开始菜单与桌面快捷方式。
- [Windows x64 绿色版 · InspirationCollector-Portable-0.2.2.exe](https://github.com/everalone/inspiration-collector/releases/download/v0.2.2/InspirationCollector-Portable-0.2.2.exe)：单文件，双击启动。

两种版本使用同一默认数据目录 `%AppData%\灵感收集\`，无需另装 Node.js。安装包未做代码签名，Windows SmartScreen 可能显示提示；请核对下载来源。

首次启动填写自己的 API Key、Base URL 和支持图片输入的 OpenAI 兼容模型。手机收集默认关闭，收件箱与 ClawBot 需要自行部署、配置和绑定；源码和安装包不包含作者的服务器地址、Token、API Key 或用户数据库，不会自动使用作者的服务器或模型账户。

## 微信链接收集与标题通知

- 独立 ClawBot 桥接只接收扫码绑定者的公众号文本链接，支持同条消息多个链接、去重和持久化恢复，不需要完整 OpenClaw Agent，也不执行聊天指令。
- 入队后回复收件通知；电脑完成解析、入库并回执后，回复 `《文章名》已解析成功并导入灵感收集。` 完成标题优先采用桌面解析结果；旧记录缺标题时使用回退通知。
- 电脑关机、睡眠或应用退出时，服务器只保存待处理链接；恢复运行后才开始解析。服务器不调用模型，也不保存完整本地卡片库。
- 公众号文章卡片直接转发、图片和文件不属于当前接收格式，需要复制文本链接发送。iPhone 快捷指令入口仍可继续使用。

## 每轮最多处理三次

- 手机文章默认每轮共 **3 次：首次处理 + 2 次重试**。服务器和桌面都限制上限；`INBOX_MAX_ATTEMPTS` 可调低，不能超过 3。
- 第 3 次失败后停止自动处理。再次分享相同失败链接返回已有失败状态，不会重新计数或排队；失败记录不因超过 24 小时、历史保留期或容量回收而删除。
- 在电脑失败列表选择「重新排队（新一轮）」才会重置次数并创建新处理轮次。带旧轮次的迟到回执不会改变新一轮任务。
- ACK 回执或微信通知发送失败时，仅补发回执/通知，不消耗分析次数，也不再次调用收费模型。相同任务、处理轮次和尝试序号已有落盘结果时直接复用，覆盖结果已保存但回执尚未保存时退出的恢复场景。

尚未保存结果的中断处理仍可能在恢复后执行。一次文章处理可包含多个图片批次，因此「最多 3 次」指文章处理尝试，并非最多 3 次模型 API 请求。

## 具体到卡片和字段的失败报告

模型响应不是有效 JSON、输出截断或卡片字段不合格时，报告会记录文章名、图片批次/范围、卡片序号/名称/类型、字段和固定原因。桌面任务面板可展开查看，最终失败时 ClawBot 会回复次数与停止状态，例如：

> 《示例文章》收集失败：已尝试3/3次，已停止自动重试。
>
> 第 2 批，图片 9–15：
>
> 第 3 张卡片《示例图标库》（网站）：payload.url — 缺少必填内容。
>
> 请在电脑端查看，修正后可手动重新排队。

报告通过持久回执传递，有脱敏、长度和条数限制，不包含模型原始响应、提示词、请求头或 API Key；未知错误使用通用诊断。仍在等待重试时不发送最终失败通知，重复分享已失败链接也不再回复“已加入队列”。校验失败继续保留已存在的文章卡片和原图。

## 减少格式误判

- 五种卡片统一使用 `payload`，兼容旧顶层字段和等价格式，包括字符串色值、大小写及三位十六进制写法。
- 缺少协议但能保留的原文网址转为笔记，保存原始网址与说明，不猜测补齐链接；真实缺失、类型错误及无效颜色/网址仍进入字段报告。
- 提取请求使用 `temperature: 0` 减少采样变化，但不保证输出完全一致。格式兼容在本地完成，没有新增模型修复请求。
- 收件箱兼容公众号长链接，并修复畸形请求导致服务进程退出的问题。

## 从旧版本升级

1. 在托盘菜单退出旧程序，备份 `%AppData%\灵感收集\` 下的整个 `data/` 和 `assets/`。
2. 安装新版或启动新版 Portable，继续使用原数据目录。已有文章、卡片、图片和配置可继续读取；普通重复收藏保留手动编辑内容。
3. 若已部署手机收件箱，先停止服务并备份 `inbox.jsonl`。收件箱需同时更新 `server.mjs`、`failure-report.mjs`；使用 ClawBot 时还需更新 `clawbot-bridge.mjs`、`clawbot-messages.mjs`，共 **4 个服务端文件**，并保留私有账号和状态文件，再启动服务。
4. 桌面与服务器配套升级后，验证自己的收集、标题通知及失败报告。手机快捷指令的 URL、Token 和请求 JSON 保持不变。

仅更新安装包不会更新服务器。旧客户端/旧服务器可继续使用基本收集接口，但不具备本版完整的结构化报告、每轮停止、跨重启结果复用和旧轮次回执隔离。

手动重新排队后，如需 ClawBot 继续跟踪新一轮，请再向机器人发送该链接。已缓存但尚未发送的上一轮失败通知仍可能补发，它描述上一轮结果，不会触发重复分析。

详细步骤：[使用说明](https://github.com/everalone/inspiration-collector/blob/v0.2.2/README.md)、[收件箱部署](https://github.com/everalone/inspiration-collector/blob/v0.2.2/inbox/README.md)、[ClawBot 部署](https://github.com/everalone/inspiration-collector/blob/v0.2.2/inbox/clawbot.md)。

## 验证范围

发布准备阶段通过 128 项隔离回归测试、类型检查、核心构建、包内容边界检查及打包运行时检查；隔离浏览器验证了字段报告与三次停止文案。失败链路使用临时数据和模拟处理器验证，不向真实模型反复提交故障样例。GitHub Actions 会在标签发布时重新执行检查并构建安装包，运行结果见 [Actions](https://github.com/everalone/inspiration-collector/actions/workflows/release.yml)。
